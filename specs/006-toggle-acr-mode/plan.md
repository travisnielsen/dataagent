# Implementation Plan: ACR Mode Toggle

**Branch**: `006-toggle-acr-mode` | **Date**: 2026-04-25 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/006-toggle-acr-mode/spec.md`

## Summary

This feature enables cost optimization by allowing operators to toggle Azure Container Registry (ACR) exposure between public and private modes in the private-networking deployment. When set to public (default), the expensive private ACR build agent pool is removed, and container images are built via the public Azure-hosted ACR build task. When set to private, the private build agent pool is created and the ACR blocks public network access. The deployment workflows (API and frontend CI/CD) will be updated to select the appropriate image build path based on configured mode.

**Scope**: Terraform changes limited to `infra/private-networking/` only. Public-networking directory is out of scope and may be removed in future work.

### Structure Decision

This feature is scoped to:

1. **Terraform variables** — Single `acr_build_mode` variable (type: string, enum: public|private, default: public)
2. **Terraform resources** — Conditional agent pool resource creation/deletion via `count`
3. **ACR configuration** — Existing module output toggled (public_network_access_enabled)
4. **CI/CD workflows** — Two workflows updated to read mode from GitHub repository variable and select build execution path
5. **Documentation** — Variable examples and operator guide added

No new projects, modules, or complex state machines. The complexity is minimal (single mode toggle + conditional resource).

## Implementation Phases

### Phase 0: Research & Best Practices

**Output**: `research.md`

Research tasks:

1. Azure Container Registry conditional resource patterns in Terraform (private vs public modes)
2. Best practices for toggling private ACR build agent pools (resource lifecycle, timing, dependencies)
3. Azure ACR Build Tasks vs agent pool build execution paths (costs, network requirements, performance)
4. GitHub Actions workflow conditional patterns for selecting build execution logic
5. Terraform state convergence validation for mode switches (ensuring idempotency)

### Phase 1: Design & Contracts

**Output**: `data-model.md`, `contracts/`, `quickstart.md`

1. **Terraform Variable Schema** (`data-model.md`)
   - `acr_build_mode` (type: string, values: "public" | "private", default: "public")
   - Documentation of each mode's implications for image builds, agent pool lifecycle, and costs
   - Validation rules (required, enum constraint)

2. **API Contracts** (`contracts/`)
   - GitHub Actions workflow input contracts for mode-aware build step selection
   - Workflow output contracts (build method used, image reference, ACR endpoint)

3. **Quickstart Guide** (`quickstart.md`)
   - How operators configure ACR mode in `terraform.tfvars`
   - Expected behavior for each mode (private: agent pool present, public: agent pool absent)
   - Cost implications and decision framework
   - Workflow validation steps

4. **Agent Context Update**
   - Run `.specify/scripts/bash/update-agent-context.sh copilot` to update context with new Terraform patterns

### Phase 2: Implementation (Executed by `/speckit.tasks`)

**Output**: `tasks.md` (generated separately)

High-level implementation order:

1. Add `acr_build_mode` variable to Terraform
2. Update ACR module `public_network_access_enabled` to reference mode
3. Update agent pool resource with `count` conditional (only create when mode="private")
4. Update outputs to conditionally export agent pool name/ID
5. Update `terraform.tfvars.example` with mode examples and cost guidance
6. Update `infra/private-networking/README.md` with operator guide
7. Update `.github/workflows/cd-api.yml` to detect mode and select build path
8. Update `.github/workflows/cd-frontend.yml` to detect mode and select build path
9. Add workflow validation to confirm mode alignment between infrastructure and workflow config
10. Test mode switches (public→private, private→public) with full apply cycles

## Risk Mitigation

| Risk | Mitigation |
|------|-----------|
| Agent pool deletion takes longer than apply timeout | Document expected timeline; recommend patience during first public-mode switch; consider separate destroy job if needed |
| Workflows configured for mismatched mode | Add explicit validation in workflow to fail fast if ACR build prerequisites missing |
| Repeated applies create drift | Terraform `count` ensures clean idempotency; validate with multi-cycle test scenarios |
| Breaking existing private-mode deployments | Default is public; private-mode behavior unchanged when mode explicitly set; validate backward compat |

- SC-001: 100% of private-mode deployments result in public registry access blocked and private build pool present
- SC-002: 100% of public-mode deployments result in public registry access enabled and private build pool absent

- SC-004: API and frontend deployment workflows each complete successfully in both modes in ≥95% of validation runs

## Notes

- This plan assumes all Terraform code resides under `infra/private-networking/`.
- Public-networking will not be modified and may be removed in future work.
- The mode is driven by infrastructure configuration (`.tfvars`), not by per-deployment environment discovery.
- CI/CD workflows will read mode from a GitHub repository variable (to be defined during Phase 2).
